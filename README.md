# Штат (рабочее название)

Офис с ИИ-сотрудниками для компаний: регистрация, свои модели и ключи, CRM, задачи, одобрения, 3D-офис.

## Запуск на своём компьютере

```
npm install
npm run dev
```

Без `DATABASE_URL` данные живут в памяти сервера и пропадают при перезапуске. Вход в демо есть на странице входа.

## Проверки

```
npm run typecheck
npm run lint
npm test
npm run build
```

Тесты поднимают настоящий Postgres (PGlite) и проверяют изоляцию компаний, вход, роли, SSRF, одобрения и движок.

## База: Neon или Railway

Нужна только строка `DATABASE_URL`. `npm run db:migrate` создаёт таблицы, роль `app_tenant` и правила RLS.
Пользователь базы должен уметь создавать роли (владелец в Neon и `postgres` в Railway умеют).

## Развёртывание

| | Vercel + Neon | Railway |
|---|---|---|
| Сборка | `npm run vercel-build` (запускается сама) | `npm run db:migrate && npm run build` |
| Запуск | сам | `npm start` |
| Фоновые задачи | Vercel Cron вызывает `/api/cron`, см. `vercel.json` | сам сервер, раз в 10 секунд |
| Переменные | `DATABASE_URL`, `ENCRYPTION_KEY`, `APP_URL`, `CRON_SECRET` | `DATABASE_URL`, `ENCRYPTION_KEY`, `APP_URL` |

На бесплатном тарифе Vercel cron срабатывает раз в сутки. Для расписаний и мониторинга нужен платный тариф или Railway.

## Этажи

- **1 этаж — ИИ-отдел.** ИИ-сотрудники и руководитель ИИ (шаблон «Руководитель ИИ-отдела»). Ему ставят общую задачу, он раздаёт части свободным ИИ (`delegate_task`) и собирает итог, когда все части готовы.
- **2 этаж — Разработка.** Люди. Разработчик заходит по ссылке команды (Настройки → Люди → «Ссылка для команды», можно ограничить доменом), получает стол и ведёт свои задачи: проект, очки, ссылка на код, обсуждение. Раздел «Разработка» показывает нагрузку за неделю.
- Свет у каждого этажа свой: `npx tsx tools/assets/bake.ts 0.7 1` и `... 0.7 2`.

## Ещё внутри

- **Спринты** на втором этаже: бэклог, ошибки и функции, очки, сгорание. Закрытие спринта возвращает незаконченное в бэклог.
- **Расходы ИИ** (`/app/usage`): укажите цену модели за миллион токенов в настройках подключения, и стоимость каждой работы посчитается сама.
- **Знания** (`/app/knowledge`): регламенты, прайсы, ответы на частые вопросы. Пишут люди; ИИ-сотрудники ищут в них ответ инструментом `search_docs` и ничего в базе не меняют. Закреплённые документы ИИ видит первыми.
- **Карточка клиента**: данные, все сделки клиента, суммы в работе и выигранные, новая сделка прямо из карточки.
- **Выгрузка CSV** клиентов, сделок и задач для Excel и Google Таблиц (владелец и администраторы). Значения, похожие на формулы, экранируются; каждая выгрузка пишется в журнал аудита.
- **Уведомления** в шапке, **поиск** по Ctrl+K (разделы, люди, задачи, документы), новая задача по клавише N.

## Что важно знать

- Почты нет: приглашения и сброс пароля выдаются ссылкой, её передаёт человек. Владелец, забывший пароль, сам войти не сможет.
- Email при регистрации не подтверждается.
- В демо-компании ИИ отвечает по сценарию, выхода в интернет и ключей нет.
- Для Claude включены запасные модели: если защитный фильтр отклонил запрос, отвечает другая модель Anthropic.

## Устройство

- `src/server/db` — схема, `tenant()` (единственный путь к данным компании), миграции в `drizzle/`
- `src/server/security` — пароли, сессии, шифрование, лимиты, защита от SSRF
- `src/server/agent` — провайдеры моделей, инструменты, очередь и одобрения
- `src/server/modules` — правила продукта; `src/app/api` — тонкие обработчики
- `src/features` — интерфейс; `src/features/office` — 3D-офис
- `tools/assets` — подготовка моделей и расчёт света (`npx tsx tools/assets/bake.ts 0.7`)

После изменения `layout.ts` или `shell.ts` свет нужно рассчитать заново, иначе в консоли появится «Карта света устарела».
